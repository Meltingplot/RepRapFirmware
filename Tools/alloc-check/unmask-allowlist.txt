# Places where a region that masks interrupts can lift its mask before it ends, that RepRapFirmware may keep, see README.md
# ("Interrupts unmasked inside a region"). alloc-check.py --unmask fails for every other one. One key per line, then a comment:
#   Function [kind] -> target           kind: basepri, primask, or critical (a critical section of the function); target: the
#                                       function that holds the instruction that lifts the mask, the function itself for a
#                                       nested clear, or "indirect call"
#   path/below/src.cpp: Function [...]  static functions and functions in anonymous namespaces
#
# The list is the state of 3.7-dev at b857e3530 (RRFLibraries 3.7-dev 888b479) in Duet3_MB6HC, Duet3_MB6XD and
# Duet3Mini5plus. Each comment gives the verdict of the census in unmask-census.md and the reason:
#   SUSPECT          the mask can be lifted while code that the region protects still runs; the fix branch is in brackets,
#                    or "open"
#   SAFE-LAST        the mask is lifted by the last call of the region, and nothing that the region protects runs after it.
#                    Read the entry again when its region changes
#   SAFE-GUARDED     the path to the instruction runs only under a run-time condition that the check does not evaluate, and the
#                    condition excludes it inside the region
#   SAFE-RESTORE     the instruction that the check counts as a clear restores the state that its function saved
#   SAFE-NO-UNMASK   a call through a register: every target the firmware sets was read and none lifts the mask
# A new entry needs the reason why the mask stays in place. Better: make the call after the region.
# "make update" rewrites the list from the firmware and keeps the comments of the entries that stay.
