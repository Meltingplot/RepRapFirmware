# Raw pointers that RepRapFirmware may keep although they can be reseated, see README.md. pointer-check.py fails for every
# other one. One key per line, then a comment:
#   Class::member, Namespace::variable   members and variables with a name that is unique in the firmware
#   path/below/src.cpp: name             static variables, anonymous namespaces and anonymous classes
#
# The first list is the state of 3.7-dev at 995d16ed4 in Duet3_MB6HC, Duet3_MB6XD and Duet3Mini5plus. Each comment gives the
# type, the verdict of the census in census.md and the reason:
#   SAFE-PERMANENT  set once at start-up and never freed
#   SAFE-ONE-TASK   read and written in one task only
#   SAFE-LOCKED     the other tasks hold the lock that the writer holds
#   SAFE-ORDER      every reader has a higher priority than the writer and does not block while it holds the pointer, and the
#                   writer reseats the pointer before it frees the object
#   SAFE-NO-DEREF   never dereferenced
#   SUSPECT         a reader can reach memory that is no longer valid; the finding of census.md and its fix are in brackets.
#                   An entry stays SUSPECT until its fix is merged.
# A new entry needs the reason why the pointer is safe without a pointer class, e.g. which tasks read and write it.
# "make update" rewrites the list from the firmware and keeps the comments of the entries that stay.
# Pointers that an upstream merge brings in are added with their type and the upstream commit, like the first list; the review
# of how they are shared gives them their reason.
